# Spec-Driven Development Sample Constitution

## Core Principles

### I. Spec-Driven Development
仕様駆動開発を採用。すべての実装は spec → plan → tasks → implement の順を厳守する。

### II. REST API Focus
REST API 機能を提供。画面 UI は不要。

### III. Readability Priority
可読性を最優先とする。

### IV. Minimize Side Effects
副作用は最小化する。

### V. Testable Design
単体テストを書きやすい設計を優先する。

### VI. Performance Optimization
パフォーマンス最適化は要件化された場合のみ実施する。

## Governance

- 憲法はすべての実践に優先する。
- 修正はドキュメント化、承認、移行計画を必要とする。
- バージョン管理: MAJOR.MINOR.PATCH 形式。MAJOR: 破壊的変更、MINOR: 新原則追加、PATCH: 明確化。
